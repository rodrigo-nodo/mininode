# Privacy Data v1

> Roadmap de producto. No implica funcionalidad actualmente implementada.

## Rol de Privacy Data Core

- **Mininode:** pregunta → ordena → propone → alerta → prioriza → recuerda → evidencia.
- **Cliente:** informa → valida → completa → corrige → mantiene.
- **Herramientas adicionales:** descubren → escanean → clasifican → mapean → conectan.

## Principio técnico y de privacidad

Privacy Data debe privilegiar el inventario y la metadata. Por defecto, no necesita recibir datos personales reales.

## Componentes futuros reutilizables

El roadmap contempla estos componentes:

- Data Inventory
- Metadata Scanner
- Data Classifier
- Data Mapper
- Data Flow Mapper
- Access Mapper
- Retention Mapper
- Risk Engine
- Evidence Store
- Local Scanner
- Connectors
- Report / Action Plan

Estas piezas deben diseñarse como componentes reutilizables de Mininode, no como código acoplado exclusivamente a Privacy.

## Frontera comercial

> Privacy Data guía. Si el cliente necesita que Mininode haga trabajo adicional sobre sus sistemas o datos, se cotiza por separado.

Privacy Data no implica:

- catalogación manual ilimitada;
- desarrollo a medida;
- intervención ilimitada en sistemas;
- acceso indiscriminado a datos personales.

## Modelo comercial inicial de adicionales

Esta información es interna y no debe mostrarse en el sitio público:

- Ayuda humana especializada: 1 UF/h
- Catalogación asistida: desde 2 UF
- Metadata Scanner estándar: desde 3 UF/fuente
- Data Classifier: módulo/pieza adicional
- Data Mapper: módulo/pieza adicional
- Connector estándar: desde 3-5 UF
- Connector especial: cotización
